# ТЗ: Учёт даты зарплаты (cash-flow по циклам)

## 1. Проблема
Расчёт «сколько можно тратить в день» считался как `свободно_за_месяц / дней_до_конца_месяца`,
предполагая, что весь месячный доход уже доступен. Но если зарплата ещё не пришла, а на счёте —
конкретный остаток, это вводит в заблуждение: человек видит «можно X/день», хотя денег до зарплаты
сильно меньше.

## 2. Как считалось раньше (анализ)
- `Свободно = Доход − Обязательные − Откладываю` (`src/lib/finance/core.ts`, `freeBudgetMonthly`).
- Леджер (`tg_expenses`): `Остаток = Свободно − Σтрат + Σдоходов` за **календарный месяц**.
- `в день = Остаток / дней до конца месяца`.
- Период всегда = календарный месяц (1-е число → конец месяца).

## 3. Решение — режим «До зарплаты» (цикл)
Вводим **день зарплаты** (`payday`, 1–31). Если он задан — считаем по **циклу**:
`цикл = [последняя зарплата (вкл.) … следующая зарплата (искл.)]`.

- Граница цикла, дни до зарплаты — `src/lib/finance/pay-cycle.ts` (`cycleBounds`), МСК, с обрезкой
  31-го числа в коротком месяце, и правилом «в день зарплаты начинается новый цикл».
- **База периода** (сколько реально доступно до зарплаты) = `Остаток на счёте − Подушка`
  (`currentBalance − minimumBalance`). Это деньги, которыми можно распоряжаться, не трогая резерв.
- `Остаток = База − Σтрат_в_цикле + Σдоходов_в_цикле`.
- `в день = Остаток / дней_до_зарплаты`.
- Месячный якорь `Свободно` сохраняется как «устойчивая» цифра (для вкладок и контекста).

Если `payday` не задан (0/пусто) — поведение прежнее (календарный месяц). **Полностью обратносовместимо.**

## 4. Поток данных (везде одинаково)
```
Калькулятор (BudgetInput.payday, currentBalance, minimumBalance)
   → сохранение расчёта → calculations.payload.budget
      → бот: patchFromPayload → telegram_users (payday, current_balance, min_balance)
      → сайт/приложение: getMonthSummaryByUser (та же функция, что для бота)
```
- Единое ядро: `src/lib/telegram-bot.ts` — `periodOf()`, `computeStatus()`, `getMonthSummaryByUser()`.
  Используют и бот (`/left`, запись трат, напоминания), и API сайта (`/api/ledger/summary`), и карточка
  «Этот месяц» на сайте/в приложении.

## 5. UX
- Калькулятор: новое поле **«День зарплаты (число)»**. Пусто → месячный режим.
- Бот `📊 Остаток`: «До зарплаты DD.MM · N дней», «На счёте сейчас», «Можно тратить ≈ X/день».
- Карточка «Этот месяц» → «До зарплаты»: Доступно / Потрачено / Доп.доход / Осталось, «≈ X/день до зарплаты DD.MM».
- Напоминания и подтверждения трат используют горизонт «до зарплаты» вместо «на месяц».

## 6. Ограничения / дальнейшее
- После зарплаты остаток на счёте надо обновить (新 цикл считает от `currentBalance`). Дальше можно
  добавить авто-прогноз баланса на следующий цикл и поле «обязательные платежи до зарплаты».
- Поддержка 2 зарплат в месяц (аванс+основная) — расширение `payday` до списка дат.

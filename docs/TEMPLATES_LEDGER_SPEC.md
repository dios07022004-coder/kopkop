# ТЗ: Шаблоны бюджета + разовые корректировки + единый леджер (сайт ↔ бот)

## 1. Проблема / цель
Сейчас сохранённый расчёт («шаблон») — это статичный снимок. Нельзя:
- быстро добавить **разовый доход** («случайно прилетели деньги») или **внеплановую трату** («ЧП»);
- увидеть живую картину месяца (свободно − потрачено + доп.доход = осталось);
- автоматически прокинуть пересчитанный шаблон в Telegram с отчётом.

Цель: шаблон = живой бюджет аккаунта. Пользователь добавляет разовые суммы (+/−),
всё пересчитывается, и **сайт, приложение и бот показывают одно и то же**, с отчётом в Telegram.

## 2. Модель данных (единый леджер)
Таблица `public.tg_expenses` становится **леджером аккаунта** (и бота, и сайта):
| поле | тип | смысл |
|---|---|---|
| id | bigint PK | |
| user_id | uuid | аккаунт (главный ключ агрегации) |
| tg_id | bigint **null** | чат Telegram (если привязан) |
| amount | int | сумма, всегда > 0 |
| kind | text | `expense` (трата) \| `income` (разовый доход) |
| source | text | `tg` \| `web` — откуда внесли |
| note | text | заметка |
| day | date | день в МСК |

Агрегация за месяц **по `user_id`** (если есть), иначе по `tg_id`. Так web- и tg-записи
одного аккаунта суммируются вместе.

`остаток = свободно(месяц) − Σ expense + Σ income`, где
`свободно = доход − обязательные − откладываю` (тот же якорь, что на сайте, `src/lib/finance`).

## 3. Сценарии
1. **Разовый доход**: сайт/бот → запись `income` → остаток растёт → отчёт в Telegram.
2. **Внеплановая трата**: запись `expense` → остаток падает → отчёт.
3. **Пересчёт шаблона** (сохранение нового расчёта на сайте): бюджет+цель пушатся в
   `telegram_users`, бот шлёт «🔄 Бюджет обновлён. Свободно: X».
4. **Дневная трата в боте**: как раньше, но теперь это запись леджера — видна и на сайте.
5. **/account и калькулятор** показывают: свободно / потрачено / доп.доход / осталось / ≈ в день.

## 4. Реализация
- **БД**: миграция `tg_expenses` (kind, source, tg_id nullable).
- **`src/lib/telegram-bot.ts`** (единое ядро):
  - `ledgerTotals(key)` → `{expense, income}` за месяц по user_id|tg_id;
  - `getMonthSummaryByUser(userId)`, `getMonthEntries`, `addAdjustment`, `deleteEntry`;
  - `addAdjustment` пишет запись и, если аккаунт привязан, шлёт отчёт в Telegram;
  - `recordSpend`, `statusText`, `/goal`, напоминания считают **net** (с income);
  - бот понимает `+5000 премия` → income.
- **API** (auth по сессии): `GET /api/ledger/summary`, `POST /api/ledger/add`,
  `POST /api/ledger/delete`, `POST /api/telegram/push-budget` (синхрон после сохранения).
- **UI**: клиентская карточка «Этот месяц» в калькуляторе (для оплативших) —
  свободно/потрачено/доп.доход/осталось + «＋ Добавить» (Трата/Доход) + список с удалением.
  На `/account` — та же сводка.
- **Авто-синхрон**: после успешного сохранения расчёта клиент дёргает `push-budget`.

## 5. Дефолты (продуктовые решения)
- Разовый доход увеличивает **остаток на жизнь в этом месяце** (не копилку). Просто и ожидаемо.
- Месяц считается по МСК; новый месяц — леджер начинается с нуля (старые записи остаются в истории).
- Удаление записи доступно автору (по `user_id`).

сохранить новый расчёт → бот получает «Бюджет обновлён». `node scripts/test-tables.mjs` — схема.

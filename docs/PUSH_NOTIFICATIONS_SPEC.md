# ТЗ: Push-уведомления на телефон (после установки приложения)

## 1. Цель
Удержание и возврат пользователя в приложение/бот. После установки PWA пользователь
получает полезные напоминания, формирующие ежедневную привычку → выше retention → выше
вероятность повторной оплаты/подписки.

## 2. Что уже реализовано (база)
- Web Push: VAPID, service worker (`push`/`notificationclick`), `push_subscriptions`, рассылка из cron.
- Кнопка «Включить напоминания» в `/account` (`EnablePush`).
- Утренняя сводка оплатившим (МСК 9–11, раз в день): «Осталось … ≈ …/день».

## 3. Что нужно доработать по этому ТЗ

### 3.1 Запрос разрешения в правильный момент (UX)
- НЕ просить разрешение сразу при заходе (это убивает opt-in rate).
- Просить: (а) сразу после **установки** приложения (событие `appinstalled` → мягкий экран
  «Включить напоминания, чтобы не выходить за бюджет»), либо (б) после **первой записи траты**
  («Включить напоминания о тратах?»).
- Если отказали — не долбить; предложить повторно максимум 1 раз через 3–7 дней.

### 3.2 Типы уведомлений (триггеры и тексты)
| Тип | Когда | Текст (пример) |
|---|---|---|
| Утренняя сводка | МСК 9–11, 1/день | «Сегодня можно потратить ≈ {perDay} ₽. Осталось {remaining} ₽ до {payday}.» |
| Не записал траты | Вечер 20:00, если за день 0 записей | «Сколько потратил сегодня? Запиши — займёт 5 секунд.» |
| Перерасход | При записи, если ушёл в минус | «🔴 Перерасход {x} ₽. До зарплаты лучше притормозить.» |
| Обнови доход | В день зарплаты (payday) | «Сегодня зарплата 💰 Обнови остаток на счёте — пересчитаю бюджет.» |
| Прогресс цели | 1/неделю | «До цели «{goal}» осталось {x} ₽. Так держать!» |
| Возврат (re-engage) | Не заходил 5–7 дней | «Не теряй контроль над деньгами — загляни, что с бюджетом.» |

### 3.3 Расписание и частота
- Не более **1–2 пушей в день**. Уважать «тихие часы» (не слать 22:00–9:00 МСК).
- Все тайминги — по МСК. Дедуп по `last_push_on` (уже есть) + по типу (добавить `last_type_on`).
- Каждый пуш ведёт в нужный экран (`url`): сводка → `/app`, «обнови доход» → `/app#income`.

### 3.4 Управление
- В `/account`: тумблеры по типам (утро / вечерний нагон / цель / возврат) — таблица настроек на пользователя.
- Глобально выключить — одной кнопкой (уже есть отписка).

## 4. Техническая реализация (дельта к текущему)
- Таблица `push_prefs (user_id, morning bool, evening bool, goal bool, reengage bool)` — дефолт true.
- Расширить cron: несколько проходов (`sendPushReminders` уже есть для утра) — добавить вечерний нагон
  (если `dayExpense(today)=0`), payday-напоминание (если сегодня = payday и не слали), re-engage.
- Сегментация: только оплатившие; проверка `hasPaidAccessForUser`.
- iOS: пуши только из установленного PWA (iOS 16.4+) — на `/install` уже подсказано; экран
  запроса разрешения показывать только в `display-mode: standalone` на iOS.
- Аналитика: логировать отправки/клики (можно простым счётчиком в БД), мерить CTR пушей.

## 5. Метрики успеха
- Доля включивших пуши среди оплативших (opt-in ≥ 40%).
- DAU/MAU приложения, доля «записал трату в день».
- CTR пушей, retention D7/D30, влияние на повторные оплаты.

## 6. Этапы
1. (Сделано) База web-push + утренняя сводка.
2. Умный запрос разрешения после установки/первой траты.
3. Вечерний нагон + payday-напоминание + перерасход (по событиям).
4. Настройки типов в `/account` + re-engage + аналитика CTR.
